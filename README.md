# Pairly

Платформа для организации взрослых любительских теннисных турниров: заявки, сетки,
расписание, счёт, рейтинг, архив и два кабинета — игрока и организатора.

Публичная часть показывает календарь турниров, рейтинг, профили игроков, журнал и
регламент. Кабинет организатора ведёт турнир от черновика до финала, кабинет игрока —
заявки, матчи и историю рейтинга.

Дизайн — редакционная система: бумага, чернила, Prata + Manrope, волосяные линии.
Весь интерфейс на русском языке.

---

## Статус

Продукт работает как **Next.js UI + Go API + PostgreSQL 17** (D-017), без BaaS.

- данные — через `src/lib/api` и серверный слой `src/lib/data`;
- регистрация, подтверждение аккаунтов, заявки, сетки, матчи и рейтинг — на Go API;
- пароли хранятся как Argon2id-хэш, сессии серверные, TLS на границе;
- внутренняя сущность клуба (`club_id`, slug `mr-pushkin`) остаётся технической
  деталью развёртывания; публичный бренд — Pairly.

Подробнее: `docs/ARCHITECTURE.md`, этапы — `docs/plans/`.

## Быстрый старт

Нужен Node.js 22 (см. `.nvmrc`) и npm.

```bash
npm install
npm run dev
```

Сайт: <http://localhost:3000>

Для работы с реальными данными нужен запущенный Go API. Переменные окружения —
в `.env.example`.

## Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | Dev-сервер на 3000 |
| `npm run typecheck` | Проверка типов TypeScript (обязательна перед коммитом) |
| `npm run build` | Продакшн-сборка Next.js |
| `npm run start` | Запуск собранного приложения |

Сборка с секретным префиксом (как на Pi):

```bash
NEXT_BASE_PATH=/<secret-prefix> npm run build
```

Префикс вшивается в `basePath` Next.js, поэтому меняется только пересборкой.

## Структура

```text
src/
  app/
    (public)/          публичный сайт: главная, о платформе, турниры, рейтинг, игроки, журнал, архив, контакты
    (auth)/            вход и регистрация
    organizer/         кабинет организатора: обзор, заявки, турниры, матчи, сетки, игроки, рейтинг, контент
    cabinet/           личный кабинет игрока
  components/
    ui/                базовые примитивы
    domain/            карточки и блоки предметной области
    organizer/         инструменты организатора
    layout/            шапка, подвал, логотип
  lib/
    data/              серверный слой доступа к данным
    api/               HTTP-клиенты Go API
    domain.ts          категории, типы турниров, статусы
    types.ts           доменные типы
    bracket.ts         генератор сеток
public/images/         нейтральная обложка-заглушка и ассеты интерфейса
deploy/                nginx-конфиги и скрипты деплоя
docs/                  продукт, архитектура, дизайн, рейтинг, решения, деплой
```

Страницы не ходят в данные напрямую: только через `src/lib/data`. Бизнес-правила
и проверки прав — на Go API.

## Регистрация и подтверждение

Поток продукта:

1. Любой желающий создаёт аккаунт: имя, фамилия, email, пароль, предварительный уровень.
2. Аккаунт получает статус «на проверке» и **не может войти**.
3. Организатор открывает `/organizer/applications`, проверяет и при необходимости
   исправляет имя, фамилию и уровень, затем подтверждает или отклоняет заявку.
4. Только после подтверждения вход считается завершённым.

Подробнее: `docs/ARCHITECTURE.md`, раздел 6.

## Деплой

Приложение работает в Docker на `127.0.0.1:3010`, внешний nginx пускает его по
секретному префиксу и требует Basic Auth.

- публичный сайт — `pairly.space`;
- API и кабинет организатора — `tournaments.pairly.space`.

```bash
./deploy/deploy-pi.sh
```

Секреты читаются из `.env.deploy` (в git не попадает). Полный runbook и проверки —
`docs/DEPLOY.md`.

## Для AI-агентов

Начните с `AGENTS.md`. Кратко: русский UI, только взрослый теннис, только Lucide,
никаких новых зависимостей без причины, минимальный диф, проверка `npm run typecheck`
перед завершением.

Рядом с проектом лежит отдельная папка `mr-pushkin-league-ai` с расширенным контекстом,
runbook деплоя и генератором промтов. См. `docs/AI-WORKSPACE.md`.
