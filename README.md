# Лига Mr. Pushkin

Сайт любительской теннисной лиги клуба **Mr. Pushkin** (Санкт-Петербург, Пушкинский район):
турниры, рейтинг, игроки, новости, архив и два кабинета — игрока и организатора.

Дизайн — редакционная система «частный клуб с собственным журналом»: бумага, чернила,
Prata + Manrope, волосяные линии. Весь интерфейс на русском языке.

---

## Статус

Сейчас это **UI-прототип**:

- данные лежат в `src/lib/mock` и отдаются через `src/lib/data`;
- базы данных, серверной авторизации, платежей и загрузки файлов ещё нет;
- регистрация, подтверждение аккаунтов и действия организатора сохраняются только
  в localStorage браузера;
- демо-вход организатора открывает `/organizer` без пароля.

Целевая архитектура — Next.js 16 + PostgreSQL 17 + Drizzle ORM на собственном бэкенде,
без Supabase и других BaaS. Подробнее: `docs/ARCHITECTURE.md`.

## Быстрый старт

Нужен Node.js 22 (см. `.nvmrc`) и npm.

```bash
npm install
npm run dev
```

Сайт: <http://localhost:3000>

## Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | Dev-сервер на 3000 |
| `npm run typecheck` | Проверка типов TypeScript (обязательна перед коммитом) |
| `npm run build` | Продакшн-сборка Next.js |
| `npm run start` | Запуск собранного приложения |

Сборка с секретным префиксом (как на Pi):

```bash
NEXT_BASE_PATH=/mp-xxxxxxxxxxxxxxxx npm run build
```

Префикс вшивается в `basePath` Next.js, поэтому меняется только пересборкой.

## Структура

```text
src/
  app/
    (public)/          публичный сайт: главная, турниры, рейтинг, игроки, новости, клуб
    (auth)/            вход и регистрация
    organizer/         кабинет организатора: обзор, заявки, турниры, матчи, сетки, игроки, рейтинг, контент
    cabinet/           личный кабинет игрока
  components/
    ui/                базовые примитивы
    domain/            карточки и блоки предметной области
    organizer/         инструменты организатора
    layout/            шапка, подвал, логотип
  lib/
    data/              слой доступа к данным (сейчас — mock, позже — БД)
    mock/              демонстрационные данные
    accounts.ts        демо-хранилище аккаунтов и подтверждений
    domain.ts          категории, типы турниров, статусы
    types.ts           доменные типы
    bracket.ts         генератор сеток
public/images/         временные фотографии клуба
deploy/                nginx-конфиги и скрипты деплоя
docs/                  продукт, архитектура, дизайн, рейтинг, решения, деплой
```

Страницы не ходят в данные напрямую: только через `src/lib/data`. Это правило
сохраняется и при переходе на PostgreSQL.

## Регистрация и подтверждение

Поток продукта:

1. Любой желающий создаёт аккаунт: имя, фамилия, email, пароль, предварительный уровень.
2. Аккаунт получает статус «на проверке» и **не может войти**.
3. Организатор открывает `/organizer/applications`, проверяет и при необходимости
   исправляет имя, фамилию и уровень, затем подтверждает или отклоняет заявку.
4. Только после подтверждения вход считается завершённым.

В прототипе это работает через localStorage. Пароль хранится как SHA-256 от email и
пароля; в продакшене будет Argon2id на сервере и серверные сессии. Подробнее:
`docs/ARCHITECTURE.md`, раздел 6.

## Деплой

Текущая площадка — Raspberry Pi 5, домен `mrpushkin.duckdns.org`. Приложение работает
в Docker на `127.0.0.1:3010`, внешний nginx пускает его только по секретному префиксу
и требует Basic Auth.

```bash
./deploy/deploy-pi.sh
```

Секреты читаются из `.env.deploy` (в git не попадает). Полный runbook и проверки —
`docs/DEPLOY.md`.

## Для AI-агентов

Начните с `AGENTS.md`. Кратко: русский UI, только взрослый теннис, только Lucide,
никаких новых зависимостей без причины, минимальный диф, проверка `npm run typecheck`
перед завершением.

Рядом с проектом лежит отдельная папка `mr-pushkin-league-ai` с расширенным контекстом,
runbook деплоя и генератором промтов. См. `docs/AI-WORKSPACE.md`.
