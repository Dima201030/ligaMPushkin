# Внешняя папка для AI-агентов

Рядом с проектом лежит отдельная папка `mr-pushkin-league-ai`. Она не входит в git и
служит «рабочим столом» для нейросетей: контекст продукта, правила, runbook деплоя и
генератор промтов.

```text
<родительская папка>/
  mr-pushkin-league/       ← репозиторий продукта
  mr-pushkin-league-ai/    ← контекст и инструкции для агентов
```

Если проект переносят, папки остаются соседями: относительный путь `../mr-pushkin-league`
не меняется.

---

## Зачем отдельная папка

1. **Контекст не засоряет продукт.** Бизнес-описание, коммерческая модель, backlog и
   заметки не должны попадать в репозиторий и в сборку.
2. **Агент начинает быстрее.** Ему не нужно исследовать весь код, чтобы понять, что за
   продукт и чего делать нельзя.
3. **Секреты не коммитятся.** Папка локальная; доступы остаются в `.env.deploy` и у
   владельца.
4. **Можно менять правила без релиза.** Обновили регламент — поправили markdown.

## Правила синхронизации

- **Репозиторий — источник правды для кода.** Если код и внешняя папка расходятся,
  прав код; папку нужно обновить.
- **Внешняя папка — источник правды для контекста и runbook.** Документы в `docs/`
  дублируют ключевые правила, чтобы агент, открывший только репозиторий, не остался без
  контекста.
- Меняете продуктовое правило — обновите `AGENTS.md`, `docs/PRODUCTION-RULES.md` и
  `RULES.md` во внешней папке.
- Меняете деплой — обновите `docs/DEPLOY.md`, `deploy/` и `DEPLOY.md` во внешней папке.
- Не копируйте в внешнюю папку пароли и токены. Только имена переменных и путь к
  `.env.deploy`.

## Безопасность

- Папка не публикуется на GitHub и не синхронизируется в облако без шифрования.
- Не вставляйте её содержимое в публичные чаты и тикеты.
- Если папка попала в чужой доступ — смените пароль Basic Auth, секретный путь и
  SSH-ключи.
