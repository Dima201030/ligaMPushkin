# План разработки лиги Mr. Pushkin

**Ревизия 4 от 18.11.2026.** Ревизия 3 предполагала бэкенд внутри Next.js + Drizzle.
Ревизия 4 (D-017): **отдельный API на Go**, UI на Next.js, PostgreSQL 17, безопасность
канала и паролей раньше доменных фич. Один клуб (D-018). Детские/юношеские
соревнования вне продукта.

**Связанные документы:**
- `docs/ARCHITECTURE.md` — стек Go+Next, crypto, деплой, бэкапы.
- `docs/DECISIONS.md` — D-017, D-018 и журнал.
- `docs/RATING.md` — формула очков (на согласовании).
- `../mr-pushkin-league-ai/ROADMAP.md` — актуальные этапы.

**Цель:** превратить UI-прототип в продакшн: публичный сайт, кабинеты, Go API с
безопасной авторизацией, турниры, сетки, матчи и рейтинг.

**Ключевые решения:**
- UI: Next.js 16. API: Go 1.23+ (chi, pgx, sqlc, goose). Без Supabase/BaaS.
- Пароли: только Argon2id; проверка по хэшу, никогда plaintext/`==`.
- Канал: TLS на nginx; Go и Postgres только на localhost / внутренней сети.
- Секреты в БД: AES-256-GCM (`APP_ENCRYPTION_KEY`). Бэкапы: `age`.
- Сессии в Postgres, токен в HttpOnly-cookie.
- Роли: player → organizer → owner → superadmin.
- Один клуб. Онлайн-оплаты нет. Парные заявки входят.
- Деплой: Compose на Pi 5 + nginx + DuckDNS; позже Selectel.

**Текущее состояние (ноябрь 2026):**
- готовы дизайн-система, публичный сайт, кабинеты, генератор сеток (в UI);
- данные — mock; Go API и Postgres ещё не внедрены;
- регистрация — localStorage (временный прототип);
- UI задеплоен на Pi за Basic Auth / секретный путь;
- `npm run typecheck` проходит.

## 2. Роли и сценарии

| Роль | Возможности |
|---|---|
| Гость | Турниры, рейтинг, профили, новости, архив, события; регистрация |
| Игрок | Свой профиль, заявки (в том числе парные), матчи, рейтинг, уведомления |
| Организатор | Турниры, заявки, сетки, матчи, игроки, рейтинг, контент |
| Владелец | Всё выше + организаторы, настройки клуба, ручные корректировки, аудит |
| Superadmin | Всё выше + владельцы, интеграции, бэкапы, миграции, системные флаги |

**Ключевые сценарии:**

1. Игрок регистрируется, подтверждает email, подаёт заявку в одиночку или парой.
2. Организатор создаёт турнир, задаёт регламент, открывает регистрацию, подтверждает заявки.
3. Организатор генерирует сетку автоматически или правит вручную, публикует.
4. Организатор вносит счёт; победитель идёт дальше, рейтинг пересчитывается.
5. Игрок видит свои матчи, очки и историю рейтинга.
6. Владелец управляет организаторами и контентом, смотрит аудит.
7. Superadmin проводит обслуживание, видит журнал, не может удалить аудит.

**Правила superadmin:**
- создаётся только CLI-командой на сервере, не через регистрацию;
- 2FA обязательна;
- не может удалять аудит и незаметно менять результаты;
- не может напрямую задать пароль владельцу — только ссылку на сброс и разблокировку;
- все действия видны владельцу, еженедельная сводка;
- нельзя снять последнего owner/superadmin.

## 3. Архитектура

Подробно — в `docs/ARCHITECTURE.md`. Кратко:

```text
Браузер
  → nginx (TLS 1.2+/1.3, лимиты, статика)
    → Next.js 16 (только UI)          :3010
    → Go API (auth, RBAC, домен)      :3020
         → PostgreSQL 17 (pgx/sqlc/goose)
         → /data/uploads
         → SMTP
```

**Принципы:**

- **Разделение.** UI не ходит в Postgres. Вся мутация и auth — в Go.
- **Безопасность сначала.** TLS снаружи → Argon2id → сессии → AES-GCM секреты → потом фичи.
- **Пароли.** Только хэш; verify constant-time; запрещён plaintext/`==`.
- **Права на сервере.** Middleware + RBAC на каждом защищённом маршруте.
- **Транзакции.** Заявка, вместимость, счёт, пересчёт — атомарно в Go/SQL.
- **Секреты только в env.** Не в `NEXT_PUBLIC_*`, не в git.
- **Время.** БД UTC, UI Europe/Moscow.

**Зависимости API (Go):** chi, pgx, sqlc, goose, `golang.org/x/crypto`.
**UI:** Lucide уже есть; HTTP-клиент к `/api` вместо localStorage auth.

## 6. Рейтинг

Полная формула и примеры — в `docs/RATING.md`. Базовые значения до согласования:

- очки за число побед в сетке 16: 0 → 30, 1 → 75, 2 → 135, 3 → 210, 4 → 300;
- коэффициент размера `sqrt(n/16)`, ограничен 0.6–1.6;
- категории: Masters 1.6, Challenger 1.3, Futures 1.0, Rookies 0.8, Beginners 0.6, Newcomers 0.4;
- типы: одиночный 1.0, парный 0.8, микст 0.8, кубок 1.4, финал 1.5, команды 0.9;
- в зачёт — лучшие 10 одиночных и 5 парных за 52 недели;
- Elo: старт 1200, K 32/24/16, парный K вдвое меньше;
- техническая победа: 50% очков, Elo не меняется.

**До этапа 6 нужно утвердить:** коэффициенты, размер зачёта, отдельную парную таблицу, стартовые рейтинги, правила категорий.

Реализация:

- `src/lib/rating.ts` — чистые функции, покрытые unit-тестами;
- `server/services/ratings.ts` — транзакции, события, снимки;
- ночной пересчёт и пересчёт после турнира идемпотентны;
- ручная корректировка только owner/superadmin с причиной и записью в аудит.

## 7. Регламент и сетки

Организатор должен уметь и автоматически, и вручную.

### 7.1 Регламент

- Форма с пресетами: олимпийская, круговая, группы + плей-офф, двойное выбывание.
- Поля: размер сетки, best of, формат сета, тай-брейк, порядок посева, bye, третье место, лимит участников, лист ожидания, правила отмены, текст регламента.
- Версии: изменение после публикации создаёт новую версию, старая остаётся в истории.
- Валидация: нельзя сохранить противоречивый регламент (например, 3 сета при best of 2).

### 7.2 Сетка

- Автогенерация из подтверждённых заявок.
- Посев: рейтинг / очки / вручную / случайно.
- Ручной редактор: перестановка игроков, bye, добавление пары, блокировка слота.
- Перестановка доступна и с клавиатуры, не только drag-and-drop.
- Публикация создаёт матчи и стороны; черновик можно пересоздать.
- После ввода результатов перестановки запрещены без отката и подтверждения.
- Экспорт CSV и печать — уже в прототипе.

## 12. Риски

| Риск | Вероятность | Влияние | Мера |
|---|---|---|---|
| SD-карта Pi выходит из строя | высокая | потеря сервера | только SSD/NVMe, ежедневный offsite-бэкап, restore-тест |
| Домашний интернет или питание | средняя | простой | UPS, мониторинг, резервный канал, позже Selectel |
| CGNAT у провайдера | средняя | нет внешнего доступа | проверить на этапе 1; иначе Cloudflare Tunnel с отдельным доменом или Tailscale Funnel |
| Ошибка в RBAC открывает чужие данные | средняя | критично | deny by default, матрица тестов, ревью каждого action |
| Утечка секретов | средняя | критично | env 600, gitleaks, ротация, без секретов в клиенте |
| Формула рейтинга вызывает споры | высокая | доверие игроков | опубликовать правила и примеры, версия конфига, апелляция к организатору |
| Ручной редактор сетки сложен | средняя | срыв этапа 5 | начать с перестановок и блокировок, drag-and-drop позже |
| Один разработчик | средняя | остановка | документация, runbook, доступы у клуба, bus factor |
| Мультиклубность понадобится внезапно | низкая | миграция схемы | `settings` и абстракция сервисов; `club_id` отдельной миграцией |
| Письма в спаме | средняя | игроки не видят статусы | SPF/DKIM/DMARC, прогрев, статус в кабинете |
| Pi не тянет сборку | средняя | долгий деплой | сборка arm64 в GitHub Actions, образ в GHCR |
| Нагрузка в день турнира | низкая | медленно | кэш, индексы, пре-генерация фото, тест 200 читателей |

## 14. Коммерческая модель и сопровождение

Продукт продаётся клубу как работающий сайт с поддержкой; это влияет на архитектуру и передачу.

**Что фиксируем в договоре:**

- **Владение.** Код, база и инфраструктура — разработчика; клуб получает неисключительную лицензию на использование и право выгрузить свои данные.
- **Домен.** Оформляется на клуб или на разработчика по согласованию; при расторжении передаётся клубу.
- **Ежемесячно входит:** хостинг, домен, TLS, ежедневные бэкапы, мониторинг, обновления безопасности, 2 часа мелких правок и консультаций.
- **Отдельно:** новые функции, дизайн, фото, тексты, импорт архива, интеграции, обучение новых сотрудников.
- **SLA:** P1 (сайт недоступен, утечка, потеря данных) — реакция 4 часа; P2 (сломан сценарий) — 2 рабочих дня; P3 (косметика) — в плановом порядке.
- **Плановые работы:** окно согласуется за 2 дня, кроме срочных исправлений безопасности.
- **Данные при расторжении:** выгрузка в течение 30 дней, затем удаление по акту; бэкапы хранятся 90 дней.
- **Доступ superadmin** нужен для сопровождения; владелец видит его действия в аудите.

**Что это значит для кода:** экспорт данных, runbook восстановления, версионирование миграций и отсутствие привязки к домашней сети обязательны с первого дня.

## 15. Критерии готовности к запуску

**Функционально:**
- [ ] Гость видит турниры, рейтинг, профили, новости, архив из БД.
- [ ] Игрок регистрируется, подтверждает email, входит, подаёт одиночную и парную заявку, отменяет.

- [ ] Владелец управляет организаторами и контентом, видит аудит.

- [ ] Секретов нет в клиенте и git.
- [ ] Бэкап восстановлен на чистой машине.
- [ ] Аудит append-only; действия superadmin видны владельцу.

**Эксплуатация:**
